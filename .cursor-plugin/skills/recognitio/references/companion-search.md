# Companion search readings

This file carries the readings of the companion tier the skill text points at. The word boundary, the name forms, the carrier encodings and the scope of the search all follow these readings, and the packet check recounts the tier under the same readings.

## The word boundary

A gathered term is credited with a line only where the term word matches the line. The character before the match and the character after it must each be a non word character or the edge of the line. The boundary is read in Unicode. A character that is a letter or a digit or a mark in any script is a word character, as the underscore is, so an accented letter standing against a match holds the boundary shut in the same way an ASCII letter does, and a term standing inside a longer identifier is not credited however the identifier is spelled. A term that begins with a mark or ends with a mark is held to the same boundary at that end.

## The name forms

One name can stand in two Unicode normalisation forms that read as the same name and differ as byte strings, a composed form holding an accented letter as one codepoint and a decomposed form holding a plain letter and a combining mark. The platforms and tools that write file names and the tools that write file contents do not all write the same form. A changed module is therefore searched under both forms of its stem, and a hit credited under either spelling stands as evidence about the one module. The one exception stands where two files at the head carry the two spellings of one stem as their own names, because then the other spelling names the other file and crediting it would credit the wrong module, so in that tree the module is searched under its own spelling alone. The matcher applies the same rule inside a line, so a mention written in the other form matches the term that names it.

## The carrier encodings

The search itself is a byte search for the plain term, and two carrier forms defeat a byte search while carrying ordinary text. A file saved in UTF-16, the default save format of a common Windows editor family, interleaves a NUL byte after every ASCII character, so no plain term can match its bytes. Carriers standing in that form at the head are found by their byte order mark, read decoded, and matched under the same word rule, and their context lines are read from the decoded text. A carrier written in UTF-16 with no byte order mark is not detected and is not read as UTF-16 anywhere in this tier, and the absence sentences the sections print are claims about marked and plain carriers, so a reader who knows a carrier stands in the unmarked form reads an absence under that scope. A carrier whose bytes carry a NUL outside a UTF-16 reading is read as a binary file and yields no companion lines at all, and a hit the byte search credited inside it is named in the packet cap notes as a context that could not be read rather than printed. A mark led decoding is accepted as a UTF-16 reading only when the decoded text still reads as text under the reading the reader states, so a mark standing in front of a plain body cannot turn that body into fabricated lines. A carrier whose bytes are not valid UTF-8, one accented byte in a legacy encoded comment being the ordinary shape, is read through a conversion that carries every byte to the character of its value, so its ASCII lines read exactly as written and no line it carries is dropped for the sake of one byte. The call sites tier reads its context lines and the imports tier reads its import lines through that reader. The change tier keeps its strict reading and is untouched by this one.

## The scope of the search

The search reads the reviewed tree alone. Content inside a submodule stands in its own repository and is not read, whether or not the working tree has initialised it. Where a submodule stands in the tree at the head, the sections that would otherwise print a bare absence sentence name the submodule paths as standing outside the search, beside the sentence, so the absence is scoped to the tree the search reads and never reads over the submodule content. A caller reached only through a symlink whose target stands outside the tree is outside the search on the same ground, and the absence sentence remains a claim about the head tree alone. The gather reads definitions, and a name carried only by a re-export list defines nothing in the file that carries the list, so that name is not gathered from that file and its callers are not sought under it.
